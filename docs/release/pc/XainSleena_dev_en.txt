XAIN'D SLEENA (PC) - technical description of the parameters (for programmers)
==============================================================================

The program emulates the Xain'd Sleena arcade board (Technos 1986), following
the MAME 0.289 driver (xain.cpp) and the MiSTer FPGA core. It runs the original
ROMs of the MAME set "xsleena":
  - 3x 6809 at 1.5 MHz (main, sub, sound): a C core (m6809.c, lockstep with
    MAME traces: 1.16 million instructions, 0 differences);
  - MC68705P5 (protection, 3 MHz) with the Taito interface;
  - 2x YM2203 (FM + SSG, MAME's ymfm ported to integer C);
  - video: 8x8 text, two scrolling 16x16 backgrounds, sprites, 8 priority
    modes, 512 x 12 bit palette.
Arcade rate: 57.44 Hz (6 MHz / 384 / 272), 272 lines of 96 6809 cycles.
PC version: C99 + SDL2 (MSYS2 UCRT64), keyboard only. The same emulation as
on the Amiga, so it is also used for checks and for analysing bug reports.
The full story of the port, measurements and decisions: docs/PORTING.md in the
port's repository.


OPTIONS
-------

  XainSleena.exe [options]   (next to SDL2.dll)

  -rompath DIR        where to look for the ROMs (repeatable); always also
                      . roms rom ROM and the program's folder. The MAME zip
                      (xsleena.zip), a folder xsleena or the loose files;
                      CRCs as in MAME; the MCU code pz-0.113 is needed
  -scale N            window magnification [3]
  -lives N            3, 4, 6 or inf (DSW1 bits 7-6: C0, 80, 40, 00)
  -easy               half the damage on foot (see below)
  -veryeasy           a quarter of the damage on foot
  -arcade             start as the arcade (see below)
  -dsw0 HH -dsw1 HH   DIP switches [3F FF as MAME]. DSW0: bits 0-1 / 2-3
                      coins B / A, 4 demo sounds, 5 allow continue, 6
                      cabinet, 7 flip screen. DSW1: bits 0-1 arcade
                      difficulty (3 Easy .. 0 Hardest), 2-3 game time, 4-5
                      bonus lives, 6-7 lives
  -nosound            no sound (the sound CPU and the YM2203 are not
                      emulated, the rest stays exact)
  -samples FILE       sound from samples (default XainSleena.snd next to
                      the program, one folder up, . or a ROM folder);
                      -emusound forces the emulation
  -fmdiv N            FM every Nth sample [1 = exact]
  -rate HZ            sound output rate [44100]
  -wav FILE           also write the sound to a WAV file (mono, 16 bit)
  -loadstate FILE     start from a machine state (Amiga F10:
                      RAM:XainSleena-state.bin)
  -frames N           quit after N frames
  -fast               no 57.44 Hz pacing
  -headless           no window and no sound (tests)
  -shots DIR LIST     screenshots DIR/frame_NNNNN.bmp (LIST:
                      100,200,1000-1100/10; frame N as in MAME)
  -dump DIR LIST      memory dumps (tools/mame_capture.lua format)
  -script LIST        timed inputs, e.g. "1200:+coin1,1206:-coin1"
                      (coin1 coin2 start1 start2 up down left right fire
                      jump p2up p2down p2left p2right p2fire p2jump)
  -slice N            CPU interleave quantum in cycles (divides 96)
  -stats              emulation time per frame every 2 s

Keys (the key standard of all ports): cursor keys move, Z = button 1
(shoot), X = button 2 (jump / extra weapon); up on foot = jump (arcade
button 2 while xain_on_foot: $0039 game running, $0041 = 1, $0053 bit 7 =
0, $0052 & 0F = 2), in the flying stages it only moves; Y = button 2 (extra
weapon); P pause, 1 / 2 start, 5 / 6
coin, F3 reset, Esc quit.


GAME (options not in the original)
----------------------------------

Default start (without -arcade): coins are inserted while no game runs and
fewer than 2 credits are left (through the coin input, 6 frames on / 24 off);
the start screen shows LEFT 1P OR RIGHT 2P and cursor left / right = start
1 / 2. Continue screen: PRESS FIRE TO CONTINUE, a new shoot press holds the
start button the game waits for ($003B bit 0), no credit -> a coin. The
texts are changed in memory (only if the original bytes are there); the
code change at 841B/8421 keeps the byte sum of the ROM 4000-EFFF (the game
computes it at boot; with a wrong sum it sets $1C1B and the flying stages
have no enemies after a death).

-easy / -veryeasy (half / a quarter of the damage, a damage of 1 counts
every second / fourth hit): the health $0056 (bits 0-5, full 10, bit 7 redraw the bar, bit 6 the
knock-back side) is lowered by the sub CPU in bank 1 7015 (through FE36 ->
FF00: STB $3000, JSR $7000, STB $3000). At the bank write from PC FF05 the
emulator adds 16 to the health; at the bank write from PC FF0D it takes the
damage from the difference and subtracts half of it (a damage of 1 counts
every second hit; at 0 it sets the death itself: $1073 bit 0). The ROM is
unchanged. The flying stages are not affected.


CPU RACE FIX
------------

The main CPU's main loop changes the byte $3D with LDA <$3D / ORA #n /
STA <$3D (8703, 8743, 879B, 87C0) with interrupts enabled, while the IRQ
from the sub CPU (80B9) sets bits 2 and 3 in it (command acknowledge). An
IRQ between the LDA and the STA wiped these bits and both CPUs waited for
ever. The emulator does not take the main CPU's IRQ at 8705 8707 8745 8747
879D 879F 87C2 87C4 (it comes 1-2 instructions later).


RELEASE NUMBER
--------------

XAIN_VERSION in port/src/xain.h: the window title and (without -arcade)
RELEASE x.y.z on the start screen instead of CREDIT n (text 07 moved to
unused zeros of bank 1 at 7790, the credit count 8188 LDA #$04 / JSR $A154
-> LDA #$9E / JSR $80DB (RTS), the ROM sum unchanged). Every release raises
the number and adds its changes to XainSleena_release_en.txt.


SOUND FROM SAMPLES
------------------

The file XainSleena.snd: recordings of the sound commands (latch 3A08), made
from your own ROMs with the tools of the repository:
    sh tools/mksndrip.sh                        -> build/sndrip.exe
    build/sndrip.exe -rate 22030 -max 150 DIR
    python tools/snd_loop.py DIR                (finds the music loops)
    python tools/make_sndpack.py DIR XainSleena.snd
About 26 MB, 22030 Hz. The file must not be distributed (it comes from the
ROMs).
