XAIN'D SLEENA - technical description of the parameters (for programmers)
=========================================================================

The program emulates the Xain'd Sleena arcade board (Technos 1986), following
the MAME 0.289 driver (xain.cpp) and the MiSTer FPGA core. It runs the original
ROMs of the MAME set "xsleena":
  - 3x 6809 at 1.5 MHz (main, sub, sound): a C core (m6809.c, lockstep with
    MAME traces: 1.16 million instructions, 0 differences) and a 68k assembler
    core generated by a script (tools/gen_6809_68k.py, Lockstep with the C core);
  - MC68705P5 (protection, 3 MHz) with the Taito interface;
  - 2x YM2203 (FM + SSG, MAME's ymfm ported to integer C);
  - video: 8x8 text, two scrolling 16x16 backgrounds, sprites, 8 priority
    modes, 512 x 12 bit palette; a line by line reference renderer and a fast
    whole frame renderer (Amiga: incremental in blocks).
Arcade rate: 57.44 Hz (6 MHz / 384 / 272), 272 lines of 96 6809 cycles.
The full story of the port, measurements and decisions: docs/PORTING.md in the
port's repository.

Parameters: Shell arguments or icon Tool Types (an entry in brackets is
switched off). Case does not matter. Defaults in [ ].


ROMS
----

ROMPATH=dir   (up to 4 times)
  Where to look for the ROMs. Also always PROGDIR:, PROGDIR:rom,
  PROGDIR:roms, PROGDIR:ROM. Accepted: the MAME zip (xsleena.zip, built-in
  inflate), a drawer xsleena or the loose files; CRCs checked as in MAME
  (pb-0.ic24 or pb-01.ic24). The MCU code pz-0.113 is needed; bootstrap.bin
  is not.


VIDEO
-----

SCREEN=WINDOW|FULL   [WINDOW; icon: FULL]
  FULL: an own screen in the best mode for the picture (on RTG a mode of the
  graphics card, 16 bit preferred), a borderless backdrop window, the
  picture centred.

SCALE=1|2|3   [2; icon: 1]
  Magnification of the 256x240 picture (pixels repeated).

VIDEO=BLIT|WPA|WCP   [16/8 bit: BLIT, 32 bit: WPA, no Picasso96: WCP]
  BLIT: the picture on the card (friend bitmap), changed blocks written
        with long word writes only, then BltBitMapRastPort of the changed
        rectangle.
  WPA:  the picture in Fast RAM in the screen format, p96WritePixelArray.
  WCP:  WriteChunkyPixels with pens. NORTG = VIDEO=WCP.

FRAMESKIP=AUTO|n   [AUTO]
  The arcade logic always runs at 57.44 Hz. AUTO: pictures are left out
  when the Amiga falls behind (at most 3 in a row); n: 1 of n+1 drawn.

RENDER=LINE   (test) the reference renderer, line by line during the frame.
REDRAW        (measurements) every drawn picture sent whole.
MOVE16=OFF    (measurements) copies to VRAM with long moves, not MOVE16.


SOUND
-----

SOUND=PAULA|AHI   [PAULA]
  PAULA: audio.device, 8 bit, period 161 (22030 Hz), Chip RAM buffers
         filled as they play.
  AHI:   AHI_AllocAudio, 16 bit.

NOSOUND
  No sound: the sound CPU and the YM2203 are not emulated at all (nothing
  else reads them, so the rest stays exact).

FMDIV=1|2   [2; PC: 1]
  2: FM output computed every second sample (phases and envelopes at the
  full rate).

SAMPLES=file | EMUSOUND
  Sound from samples instead of the emulation: the file XainSleena.snd
  (looked for as SAMPLES, in PROGDIR: and the ROM drawers, loaded whole into
  Fast RAM). The game writes commands to the sound latch (3A08); sndplay.c
  plays the recordings of those commands (1 music voice + 5 effects,
  loops). The file is made from your own ROMs on the PC with the tools of
  the repository:
    sh tools/mksndrip.sh                          -> build/sndrip.exe
    build/sndrip.exe -rate 22030 -max 150 DIR     (every command on its
                                                  own, tools/sndrip.c)
    python tools/snd_loop.py DIR                  (finds the music loops)
    python tools/make_sndpack.py DIR XainSleena.snd
  (details: docs/PORTING.md, chapter 13). About 26 MB, 22030 Hz. The file
  must not be distributed (it comes from the ROMs). EMUSOUND forces the
  emulation even with the file. SNDLOG (test): the sound commands go to
  RAM:XainSleena-snd.txt.


CONTROLS
--------

CONTROL=JOY1|JOY2|KEYBOARD   [JOY1]
  JOY1: a one button joystick; up = jump, but only while the player is on
        foot (RAM: $0039 game running, $0041 = 1 play scene, $0053 bit 7 =
        the ship, $0052 & 0F = 2 moving). In the flying stages up only
        moves, button 2 (Space) = the extra weapon.
  JOY2: the second joystick / pad button = arcade button 2.
  KEYBOARD: the joystick port is not read.
  CD32 pad: red fire, blue button 2, play start 1, green coin, yellow
  start 2. ReadJoyPort once per frame.

JOYPORT=BOTH
  A joystick in the mouse port too.

Keyboard always: cursor keys, Ctrl / Z = button 1, Space / Alt / X =
button 2, 1 / 2 start, 5 / 6 coin, P pause, F3 reset, F10 save the machine
state, Esc / close window / Ctrl-C quit.


GAME (options not in the original)
----------------------------------

START=EASY|ARCADE   [EASY]
  EASY: coins are inserted while no game runs and fewer than 2 credits are
        left (through the coin input, 6 frames on / 24 off); the start
        screen shows LEFT 1P OR RIGHT 2P and joystick left / right = start
        1 / 2. Continue screen: PRESS FIRE TO CONTINUE, a new fire press
        holds the start button the game waits for ($003B bit 0), no credit
        -> a coin. The texts are changed in memory (only if the original
        bytes are there); the code change at 841B/8421 keeps the byte sum
        of the ROM 4000-EFFF (the game computes it at boot; with a wrong sum
        it sets $1C1B and the flying stages have no enemies after a death).
  ARCADE: as the arcade (coins 5 / 6, start 1 / 2).

LIVES=3|4|6|INF
  DIP switches (DSW1 bits 7-6: C0, 80, 40, 00 = infinite).

DIFFICULTY=NORMAL|EASY   [NORMAL]
  EASY: half the damage on foot. The health $0056 (bits 0-5, full 10, bit 7
  redraw the bar, bit 6 the knock-back side) is lowered by the sub CPU in
  bank 1 7015 (through FE36 -> FF00: STB $3000, JSR $7000, STB $3000). At
  the bank write from PC FF05 the emulator adds 16 to the health; at the
  bank write from PC FF0D it takes the damage from the difference and
  subtracts half of it (a damage of 1 counts every second hit; at 0 it sets
  the death itself: $1073 bit 0). The ROM is unchanged. The flying stages
  (health 0, one hit kills) are not affected.

DSW0=hh DSW1=hh   [3F FF as MAME]
  DIP switches. DSW0: bits 0-1 / 2-3 coins B / A, 4 demo sounds, 5 allow
  continue (1 = yes), 6 cabinet, 7 flip screen. DSW1: bits 0-1 arcade
  difficulty (3 Easy, 2 Normal, 1 Hard, 0 Hardest), 2-3 game time, 4-5
  bonus lives, 6-7 lives.


CPU RACE FIX
------------

The main CPU's main loop changes the byte $3D with LDA <$3D / ORA #n /
STA <$3D (8703, 8743, 879B, 87C0) with interrupts enabled, while the IRQ
from the sub CPU (80B9) sets bits 2 and 3 in it (command acknowledge). An
IRQ between the LDA and the STA wiped these bits and both CPUs waited for
ever (the picture stops, the music plays; about once in some tens of
thousands of frames). The emulator does not take the main CPU's IRQ at
8705 8707 8745 8747 879D 879F 87C2 87C4 (it comes 1-2 instructions later).


RELEASE NUMBER
--------------

XAIN_VERSION in port/src/xain.h: the program's $VER, the PC window title and
(START=EASY) RELEASE x.y.z on the start screen instead of CREDIT n (text 07
moved to unused zeros of bank 1 at 7790, the credit count 8188 LDA #$04 /
JSR $A154 -> LDA #$9E / JSR $80DB (RTS), the ROM sum unchanged). Every release
raises the number and adds its changes to XainSleena_release_en.txt.


MEASUREMENTS AND TESTS
----------------------

STATS | STATS=FULL
  Window title every 2 s: "Xain 57.4 fps (drawn 40) CPU 80% ..."
    fps     frames of the arcade logic (full speed 57.44)
    drawn   pictures drawn per second
    CPU     CPU load
  STATS=FULL adds times: emu (emulation), render, present (sending to the
  card), blocks, snd and the emulation split A/B/S/YM/MCU (main, sub, sound
  CPU, YM2203, MCU). On the full screen the title is not visible (AmiAgent
  reads it).
VERIFY       (test) reads the picture back from the card and compares the
             blocks with the reference.
CPU=C        the 6809 core in C instead of assembler (about 11x slower).
MEMO=OFF     no replay of the waiting main CPU's time slices.
SUBFAST=OFF  the waiting sub CPU through the core.
HLE=ON       the sprite list routine DCEC-DE88 translated to C.
SLICE=n      CPU interleave quantum in cycles (divides 96) [96].
All fast paths are exact (compared with the slow ones: memocheck, Lockstep).

F10: saves the whole machine state (3x 6809, MCU, RAM, registers, YM timers,
the memo table; portable big endian format, about 21 KB) to
RAM:XainSleena-state.bin and a short description (CPU PCs, options) to
RAM:XainSleena-state.txt. On the PC: XainSleena.exe -loadstate FILE.
Watchdog: when no new frame comes for 3 s, the state of the program's task
goes to RAM:XainSleena-hang.txt.

Measured on an A1200 (68060 100 MHz, Warp 1260, RTG 16 bit, SCALE=1, demo):
logic at 57 frames/s (full speed) without sound and with samples, with
emulated sound (Paula) 25-41 frames/s. At 50 MHz about 2 times slower.


PC VERSION (Windows, SDL2)
--------------------------

  XainSleena.exe [options]   (next to SDL2.dll; keyboard only)
  -rompath DIR        where to look for the ROMs (repeatable); always also
                      . roms rom ROM and the program's folder
  -scale N            window magnification [3]
  -lives N            3, 4, 6 or inf
  -easy               as DIFFICULTY=EASY
  -arcade             as START=ARCADE
  -dsw0 HH -dsw1 HH   DIP switches
  -nosound            no sound
  -samples FILE       sound from samples (default XainSleena.snd next to
                      the program); -emusound forces the emulation
  -fmdiv N            FM every Nth sample [1]
  -rate HZ            sound output rate [44100]
  -wav FILE           also write the sound to a WAV file
  -loadstate FILE     start from a machine state (Amiga F10)
  -frames N           quit after N frames
  -fast               no 57.44 Hz pacing
  -headless           no window and no sound (tests)
  -shots DIR LIST     screenshots DIR/frame_NNNNN.bmp (LIST:
                      100,200,1000-1100/10)
  -dump DIR LIST      memory dumps (tools/mame_capture.lua format)
  -script LIST        timed inputs, e.g. "1200:+coin1,1206:-coin1"
                      (coin1 coin2 start1 start2 up down left right fire
                      jump p2...)
  -slice N            interleave quantum in cycles
  -stats              emulation time per frame every 2 s
